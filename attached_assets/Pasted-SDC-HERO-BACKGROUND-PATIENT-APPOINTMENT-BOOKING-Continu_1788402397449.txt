SDC HERO BACKGROUND + PATIENT APPOINTMENT BOOKING

Continue working on the existing Somil Dental Clinic (SDC) frontend.

Do not change the overall blue design direction. Improve the hero and add a proper frontend appointment-booking experience.

1. HERO BACKGROUND

Make the hero background significantly better.

IMPORTANT:
A hero image is NOT required.

If there is no genuinely high-quality dental image that fits the design, do not force an image into the hero.

I prefer a clean, minimal, premium background over a random stock image.

Create a sophisticated blue-based hero background using subtle visual depth such as:

- Very subtle blue tonal layers
- Extremely soft gradients if needed
- Minimal abstract dental/medical-inspired shapes
- Subtle light effects
- Fine patterns or textures only if they genuinely improve the design
- Clean negative space

The background must remain calm and professional.

DO NOT use:

- Loud gradients
- Neon effects
- Giant abstract blobs
- Excessive glassmorphism
- 3D objects
- Excessive particles
- Busy patterns
- Distracting animations
- Random stock imagery

The hero text must remain extremely readable.

The background should make the SDC hero feel premium, modern, clean and memorable, while still looking like a professional dental clinic.

If using animation, keep it extremely subtle, slow and elegant.

The hero should look excellent even with ZERO images.

3. TREATMENT SELECTION

When a patient clicks Book Now on a treatment card, automatically open the appointment booking interface with that treatment already selected.

Example:

Dental Checkup → Appointment form opens with “Dental Checkup” selected.

Root Canal Treatment → Appointment form opens with “Root Canal Treatment” selected.

Do this using frontend state/query parameters only. No backend.

4. FORM UX

Make the booking form feel extremely polished.

Use:

- Clear field labels
- Helpful placeholders
- Excellent spacing
- Clean input styling
- Proper focus states
- Smooth transitions
- Accessible controls
- Mobile-friendly layout
- Clear validation messages
- Proper required fields

Do NOT make the form unnecessarily complicated.

The patient should be able to understand it immediately.

5. BOOKING SUBMISSION

Since there is no backend yet, create a realistic frontend submission experience.

When the patient submits:

- Validate the form
- Show a polished loading state
- Then show a clear success confirmation
- Display the submitted appointment summary
- Show selected treatment
- Show preferred date/time
- Show patient name

Clearly indicate that this is a frontend/demo booking flow until backend integration is added.

Do NOT pretend that an appointment has actually been stored in a real database.
